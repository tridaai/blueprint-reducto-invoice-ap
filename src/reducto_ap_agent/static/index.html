Remittance confirmation

A released run is a proposal. The bank answers it with a remittance advice, and confirmation reconciles that answer line by line — exactly, never within a tolerance: paid as proposed, short, over, missing, or a line for an invoice the run never contained. An advice that names no run on file is held unmatched, never guessed onto one. Confirmation is evidence; it changes no run, no export, and no approval.

The unmatched pile — the worklist

Held advices, worked by a person. The arithmetic suggests what each line might answer — an exact line the advice failed to name, a reference one edit from an invoice number, one lump covering several lines of a run, an amount exact with no reference to stand on, an amount near a line the reference names — and a suggestion confirms nothing: only a controller's link settles lines, under the same exact rule as any confirmation, and a controller may instead mark an advice not ours, with the reason on the record.

The pile is empty — every advice on file has been answered for.

AP position at close

What we owe, to whom, and how old it is — aged off due dates as of the stated date, split by the state of the money (free, in a run, part-paid with the remainder still owing), and tied to the packet's open total in the same pass. Only the remainder ages: money already instructed is shown as the paid figure beside it, never as still owed. Fraud-held money is disclosed beside the position, outside the tie. An invoice with no due date on record is UNDATED — shown, never silently bucketed.

Paid-duplicate watch

The duplicate that arrives second: an invoice that answers to one already released for payment — same supplier, same number, at the paid face or the total the released runs instructed across every part payment — is held at intake on the paid evidence below. The gate cannot decide a held record; a named controller resolves the hold, with a reason, one of two ways: confirm it (the record is refused permanently) or release it as not a duplicate (it returns to the state its own match earned). Nothing here touches the original payment — there is no clawback, only a stop on the second one.

No held duplicates — nothing on file answers to a payment already released.

New suppliers — held at the door

A payable document whose supplier is not on the master stops here: its name matched no master entry exactly, and no purchase order it references resolved it. It has not been matched and has not been fraud-screened — there is no master record to screen it against — and it is not a payable: the gate cannot decide it and no run will carry it. A name that almost matches is named as a near-miss, as evidence — resemblance enrols nobody. Two exits, both a named controller's: enrol the supplier (its bank details enter the master as version 1, with the provenance they were verified from, and every held document of the identity is released back into the pipeline and judged on its own contents), or refuse a document as not a known supplier, with the reason — per document, so one bad paper does not condemn the identity's others.

The door is clear — every document on file names a supplier on the master.

Supplier ledgers

One supplier, the whole relationship: every document the intake joined to them, each invoice's face, credits and open amount, the statement breaks still open against them, and bank details from the supplier master only — with a warning wherever a document disagreed with them. The master is versioned: the bank details shown are the version in force at the as-of, its timeline rides the ledger, and a legitimate change is recorded there with its provenance. Invoices are screened against the version in force on their own date — old details on an old invoice are clean, new details before their date are a hold. Totals tie to the position at the same as-of. A document that joined to no supplier is listed under Unmatched — never attached by resemblance, never dropped.

PO coverage

What has been billed against each purchase order, in total — the accumulation the per-invoice match cannot see. Billed is the sum over APPROVED invoices of face minus applied credits; payments settle a bill, they never shrink it, so a part-paid invoice bills in full. An order's total is the order register's, and the row says so; an order no register carries reads UNMEASURED — its billed sum listed, no verdict invented. Coverage informs the approver's gate; it never blocks it and never rewrites a match outcome.
